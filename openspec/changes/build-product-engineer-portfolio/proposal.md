## Why

The current repository is the untouched Next.js starter and does not communicate Henry Gonzalez's ability to design and ship production digital products. A focused professional portfolio is needed to turn verified work on MediSapience and CEM Digital into credible evidence for international clients and remote opportunities.

## What Changes

- Replace the starter experience with an English-first, product-led professional portfolio for a Full-Stack Developer / Product Engineer.
- Establish an implementation-ready design system, UX architecture, responsive rules, accessibility baseline, motion constraints, content governance, and quality gates before application code is changed.
- Introduce a conversion-oriented Home experience with product proof, two dominant featured projects, verified impact, services, process, technology context, a concise About section, testimonials when available, and a high-impact contact close.
- Introduce reusable editorial case-study experiences for MediSapience and CEM Nicaragua / CEM Digital.
- Add clear project/contact navigation, mobile menu behavior, external links, metadata, social previews, sitemap/robots support, performance budgets, and optional privacy-respecting analytics.
- Permit clearly non-production mock copy and illustrative product UI in local/preview implementation while source content is pending; any build containing mocks remains non-indexable and ineligible for launch.
- Require authentic, privacy-reviewed screenshots and verified metrics; unresolved evidence remains `[CONTENT NEEDED]` and is not published as fact.
- Defer a separate Work index, standalone Services/About routes, a custom project cursor, enhanced analytics, and other polish unless their P1/P2 acceptance criteria are met.
- Do not add a global dark mode, decorative 3D devices, hacker motifs, vanity metrics, skill bars, or template-style portfolio effects.

## Capabilities

### New Capabilities

- `professional-portfolio-experience`: Covers the public portfolio's information architecture, Home and case-study journeys, verified content, responsive behavior, accessible interactions, contact paths, SEO, performance, analytics, and visual-system constraints.

### Modified Capabilities

None. The project has no existing OpenSpec capabilities.

## Impact

- Application surface: `app/` routes, layouts, metadata, global styles, and future reusable UI components.
- Content/assets: authentic project screenshots, logos, portrait, testimonials, verified metrics, case-study narratives, and contact/social details supplied before publication.
- Tooling: existing Next.js 16, React 19, TypeScript, Tailwind CSS 4, ESLint, and pnpm scaffold; any additional motion or analytics dependency requires explicit implementation-phase justification.
- Public behavior: new Home and two case-study routes, responsive navigation, keyboard-accessible interactions, external/live-product links where verified, and direct contact actions.
- No API, database, authentication, or backend capability is introduced by this planning change.
